# EduLLM GPU handoffs

## OLMoE native benchmark smoke

[`run_olmoe_benchmark_smoke.py`](run_olmoe_benchmark_smoke.py) loads the pinned
`allenai/OLMoE-1B-7B-0924-Instruct` checkpoint and runs three deterministic GSM8K cases
through OLMo Eval's native `standard_olmo` runner. It uses the benchmark's own data,
few-shot formatter, scorer, request/prediction artifacts, and managed vLLM lifecycle;
there are no handwritten tutor prompts. See
[`OLMOE_BENCHMARK_SMOKE.md`](OLMOE_BENCHMARK_SMOKE.md) for the GPU command and strict
compatibility gates. The benchmark score is diagnostic and does not gate this smoke.

## Live two-machine EduLLM CAT run

Tooling to run a live Computerized Adaptive Test (CAT) where the **candidate Tutor LLM**
runs locally on the eval job's GPU and the **frozen Qwen judge** runs on a **separate
machine**, reached over HTTP. Each scenario is generated by the tutor, graded by the
remote judge criterion-by-criterion, and the next scenario is selected adaptively until
the benchmark's locked stop rule fires.

The two-machine topology needs no runner code changes: a `vllm_server` judge provider
with a `base_url` reports `requires_local_gpu == False`
([src/olmo_eval/inference/providers/config.py](../../src/olmo_eval/inference/providers/config.py)),
so `ModeRunOrchestrator` treats it as an external endpoint and validates it via
`{base_url}/version` instead of managing its lifecycle
([src/olmo_eval/runners/mode_orchestrator.py](../../src/olmo_eval/runners/mode_orchestrator.py)).

## Scripts

| Script | Runs on | Purpose |
| --- | --- | --- |
| `conform_flow_package_bank.py` | laptop (CPU) | Turn a flow-package bank into loader-ready `rubrics.jsonl` / `scenarios.jsonl` / `manifest.json`; gates on `load_fitted_bank`. |
| `build_run_config.py` | laptop (CPU) | Emit the strict `run-modes` YAML (local tutor + remote judge); frozen judge values imported from the package; self-validates via `load_mode_config`. |
| `preflight_local.py` | laptop (CPU) | No-GPU/no-network equivalent of `--check`: validates wiring, defers GPU + live `/version`. |
| `serve_frozen_judge.sh` | judge machine (GPU) | Launch the frozen Qwen judge as a persistent vLLM 0.26.0 OpenAI-compatible server. |
| `verify_judge_endpoint.py` | anywhere | Confirm `{base_url}/version == 0.26.0` and explicit `logprob_token_ids` support. |

All commands below use the no-vLLM environment so they work off-GPU on any platform:
`uv run --no-default-groups --extra edullm python ...` (the `edullm` extra only adds
scipy). The `vllm` default group pulls Linux-only wheels and is not needed for the
CPU-side steps.

## Operating point is per-benchmark and locked

Each benchmark's CAT operating point is a property of its fitted bank and is fixed in
that benchmark's `FLOW_PACKAGE.md`. It is **not** a global default and must not be reused
across banks. `build_run_config.py` defaults to biggen's locked point
(`max_se 0.12`, `min_scenarios 8`, `mwle_ridge 0.01`, MWLE, `selection trace`,
`top_n 5`, `seed 20260729`, `stop_se_method eap`); pass the target benchmark's values
for any other bank. The generator records the op-point and its source under the run
`metadata` for provenance.

## Step 1 - conform the bank (laptop)

The `biggen-cal-52models` tag ships a per-criterion parameter bank plus the benchmark's
scenarios, but not the loader triple. Extract the inputs from the tag and conform them:

```bash
mkdir -p .edullm_gen/biggen/src
git show biggen-cal-52models:eduLLM-Evals/biggen_calibration/bank/biggen_unidim_modeled.jsonl > .edullm_gen/biggen/src/biggen_unidim_modeled.jsonl
git show biggen-cal-52models:eduLLM-Evals/data/BiGGen/scenarios.jsonl > .edullm_gen/biggen/src/scenarios.jsonl

uv run --no-default-groups --extra edullm python scripts/edullm/conform_flow_package_bank.py \
  --params-bank .edullm_gen/biggen/src/biggen_unidim_modeled.jsonl \
  --scenarios   .edullm_gen/biggen/src/scenarios.jsonl \
  --out-dir     .edullm_gen/biggen/bank \
  --skills general \
  --benchmark-id biggen \
  --calibration-version biggen-unidim-52models
```

For biggen this yields 2337 fitted criteria across 669 scenarios. 52 criteria with
non-positive `general` discrimination are excluded (the runtime contract forbids
non-positive active loadings; this matches the exporter's `nonpositive: exclude`
policy), and 24 scenarios that kept no fitted criterion are dropped. Exclusions are
recorded in the manifest under `excluded_criteria` / `counts`. A multi-skill bank (e.g.
tutorbench) passes multiple `--skills` and a `--latent-correlation` matrix instead of
the default identity.

## Step 2 - generate and locally validate the run config (laptop)

```bash
uv run --no-default-groups --extra edullm python scripts/edullm/build_run_config.py \
  --bank-manifest .edullm_gen/biggen/bank/manifest.json \
  --run-id biggen_two_machine_smoke \
  --output-dir .edullm_gen/biggen/results/biggen_two_machine_smoke \
  --out-config .edullm_gen/biggen/run_two_machine_smoke.yaml \
  --judge-base-url http://JUDGE_HOST:8000/v1   # replace with the real judge host

uv run --no-default-groups --extra edullm python scripts/edullm/preflight_local.py \
  --config .edullm_gen/biggen/run_two_machine_smoke.yaml
```

`build_run_config.py` self-validates with `load_mode_config` (structure + frozen judge +
provider checks). `preflight_local.py` additionally resolves the provider graph and the
external-judge wiring, deferring only the two checks that need real hardware/network.

## Step 3 - stand up the remote judge (judge machine, GPU)

```bash
JUDGE_PORT=8000 bash scripts/edullm/serve_frozen_judge.sh
# from any host that can reach it:
python scripts/edullm/verify_judge_endpoint.py --base-url http://JUDGE_HOST:8000/v1
```

The judge is frozen to `Qwen/Qwen3.5-9B` at revision
`c202236235762e1c871ad0ccb60c8ee5ba337b9a` on vLLM **0.26.0** (required for explicit
token logprobs). Keep it in its own venv; do not upgrade the repo's vLLM pin.

## Step 4 - platform networking and submission (GPU, via the platform)

All GPU work goes through the `edullm` platform, never AWS directly
([AGENTS.md](../../AGENTS.md)). Two decisions before submitting:

- **Where the judge lives.** Host it as a persistent server the eval job can reach: a
  long-running `edullm run`/`shell` box, or a managed HF Inference Endpoint. It must be
  reachable at the `--judge-base-url` you baked into the config.
- **Egress.** Confirm the submitted tutor job is allowed to make outbound HTTP calls to
  the judge host; the CAT loop grades every selected scenario over that connection.

Platform CLI setup (run when you are ready to submit; deferred for now):

```bash
uv tool install --force git+https://github.com/edu-llm/platform
edullm --version
edullm check --json          # prices/validates from the committed tree; reaches no GPU
```

Because the image is built from a commit, the generated config and (regenerated) bank
must be committed or produced by a run step on the branch you submit.

## Step 5 - smoke first, then full run (GPU)

On the eval job, once the judge is reachable:

```bash
uv run olmo-eval run-modes --config run_two_machine_smoke.yaml --check   # live /version probe
uv run olmo-eval run-modes --config run_two_machine_smoke.yaml           # the smoke run
```

The smoke uses a small tutor (`--tutor-model`) and a capped `--max-scenarios` (default
12) to prove the end-to-end live loop and remote grading. For the full biggen run,
regenerate the config with the real candidate checkpoint (`--tutor-model`,
`--tutor-revision`) and a higher `--max-scenarios` (biggen deploys ~19 scenarios median);
the locked SE/floor/ridge stay as-is.
