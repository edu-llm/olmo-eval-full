### Runtime consumption contract

The runtime loads params via `Rubric.from_json` (`tutor_cat/schemas.py`), which reads
`obj["discrimination"]` as a **3-vector keyed by `tutor_cat.SKILLS = (content, diagnosis,
scaffolding)`** and `obj["difficulty"]` as the scalar `b`. Both artifacts therefore carry
those exact fields. Loadings are stored in the fixed 3-slot layout and each skill-set
*repurposes* the three slots (documented below and stamped into every record's
`irt_params.provenance.slot_map`).

### Skill → slot representation

**2-skill** — source `staging/calibration_mirt_full2skill.csv`
(columns `a_correctness`, `a_scaffolding`, `b`; collapse content+diagnosis → correctness):

| slot (`SKILLS`) | value |
|---|---|
| `content` | `a_correctness` (collapsed content+diagnosis) |
| `diagnosis` | `0.0` (collapsed away; recorded in metadata) |
| `scaffolding` | `a_scaffolding` (as-is) |

Presentation is not modeled. Matrix: `staging/response_matrix_full_nonopt.csv`
(sha256 `b62f6dcf…d74b9`).

**3-skill** — source `staging/run6_presentation/calibration_mirt.csv`
(columns `a_content`, `a_diagnosis`, `a_scaffolding`, `b`, which under Run 6's
slot-repurposing carry correctness / scaffolding / presentation). This is the exact bank
the 3-skill CAT eval consumes (`scripts/cat_eval_tutorbench_3skill.py::load_bank`), so the
mapping is a straight column → same-named-slot copy — the cleanest option and consistent
with the existing runtime interpretation:

| slot (`SKILLS`) | value | latent axis |
|---|---|---|
| `content` | `a_content` | correctness |
| `diagnosis` | `a_diagnosis` | scaffolding |
| `scaffolding` | `a_scaffolding` | presentation |

Matrix: `staging/response_matrix_full.csv` (sha256 `b6216bbf…f0b3`).

### Uncalibrated-item handling

Items outside a fit's block **retain their existing heuristic `discrimination` /
`difficulty` verbatim** (never zeroed). Their `irt_params` is flagged
`calibrated: false` with an `uncalibrated_reason`:

- `all_fail_zero_variance` — dropped from the fit as all-fail / zero-variance
  (2-skill: 2043; 3-skill: 2049).
- `missing_qrow` — no Q-matrix row (640 in both).

Calibrated items are stamped `irt_params.source` = `calibrated-m2pl-2skill-pilot` /
`calibrated-m2pl-3skill-pilot`, `calibrated: true`, `modeled_skills`, and a `provenance`
block (source CSV, fitter manifest, matrix csv + sha256, date, N=82, `n_items_fit`,
`slot_map`, negative-loading policy, and the pilot-baseline note).

### Negative-loading policy

The pilot M2PL fits contain a small number of **negative** discrimination loadings (a fit
artifact at N=82: 2-skill 363, 3-skill 350). The runtime validator
(`tutor_cat/dataio.py::_validate`) rejects `a < 0`, and the canonical calibrated bank
carries none, so negatives are **clamped to 0.0** and the count is recorded in each
record's `provenance.negative_loading_policy`.

### Load verification

Both files parse cleanly through `Rubric.from_json` for all 6845 records and through
`load_bank(scenarios_curated, <artifact>)` with **0 validation errors**. (Warnings are the
pre-existing "q_mapping maps to no skill (all zeros)" notices inherited from the curated
bank; they are present regardless of calibration.) `config.yaml`'s default was **not**
changed.

## Multiskill CAT harness (P2)

`scripts/cat_eval_tutorbench_multiskill.py` — a single entrypoint with a `--skills {2,3}`
flag (alias `--skill-set`). It reuses the existing internals verbatim by dispatching to the
two original, **unmodified** scripts (`cat_eval_tutorbench.py`,
`cat_eval_tutorbench_3skill.py`), so the M2PL math and the results are byte-for-byte
identical. Shared flags (`--bank --matrix --kfold-dir --out-dir --grid --se-target
--min-items --max-items --seed --no-oos`, plus `--ref-2skill` for 3-skill) are forwarded;
any flag left unset falls back to that instrument's own default.

```bash
# 2-skill instrument
python scripts/cat_eval_tutorbench_multiskill.py --skills 2

# 3-skill instrument
python scripts/cat_eval_tutorbench_multiskill.py --skills 3 --se-target 0.3 --max-items 100
```

The two original scripts are left intact.

## Ridge 1e-3 → 1e-2 before/after (2026-07-31)

Clean, ridge-only comparison through the **standard** pipeline: same matrices, same Q,
same collapse, grid 7, k=5 / seed 20260729, CAT policy floor=15 (pbis 0.05, content
balance, exposure top-5, seed 20260730). Both columns use the current curated bank (60
`exclude_from_fit` flags honoured → 2-skill 3443 items, 3-skill 4156 items), so the only
thing that changes between columns is the M2PL loadings ridge. OOS recovery `r` = CAT
harness fold-trained vs full-bank ability (`reports/cat_eval_policy/{2,3}skill`);
stability = median cross-fold (k=5) Pearson of the per-item loading.

### 2-skill `[correctness, scaffolding]`

| metric | ridge 1e-3 | **ridge 1e-2** | Δ |
|---|---:|---:|---:|
| **OOS correctness recovery r** (guardrail) | 0.919 | **0.929** | **+0.010** |
| **OOS scaffolding recovery r** | 0.554 | **0.669** | **+0.115** |
| stability `a_correctness` (k=5) | 0.790 | 0.818 | +0.028 |
| stability `a_scaffolding` (k=5) | 0.558 | 0.618 | +0.060 |
| extreme-a (\|a_scaff\|≥6) | 22 | 6 | −16 |

### 3-skill `[correctness, scaffolding, presentation]`

| metric | ridge 1e-3 | **ridge 1e-2** | Δ |
|---|---:|---:|---:|
| **OOS correctness recovery r** (guardrail) | 0.921 | **0.934** | **+0.013** |
| **OOS scaffolding recovery r** | 0.571 | **0.648** | **+0.077** |
| OOS presentation recovery r | 0.921 | 0.937 | +0.016 |
| stability `a_correctness` (k=5) | 0.772 | 0.797 | +0.025 |
| stability `a_scaffolding` (k=5) | 0.488 | 0.590 | +0.102 |
| stability `a_presentation` (k=5) | 0.712 | 0.762 | +0.050 |

**Guardrail — HELD.** OOS correctness did not regress on either instrument; it *improved*
(2-skill +0.010, 3-skill +0.013). Scaffolding OOS recovery and every cross-fold stability
figure improved. The 3-skill fit stayed a clean optimum (multi loglik −78,703 above the
nested fold −79,234, latent R unchanged: corr↔scaff −0.484, corr↔pres 0.945, scaff↔pres
−0.559), so the 3-skill bank was shipped at 1e-2 (no anomaly).

The 1e-3 baseline column was produced fresh on the current 3443-item curated bank (fit +
k-fold + CAT under `staging/_before_ridge1e3/`), not the stale 3497-item snapshot, so the
deltas isolate ridge and are not confounded by the exclude-flag curation change.
