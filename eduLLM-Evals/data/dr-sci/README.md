# Dr. SCI (open-ended)

Dr. SCI reformatted into the Scenario + Rubric schema. Source:
https://huggingface.co/datasets/MiniByte-666/Dr.SCI — an **unofficial reproduction** of the
dataset from *"Improving Data and Reward Design for Scientific Reasoning in Large Language
Models"* (Chen et al., 2026, [arXiv 2602.08321](https://arxiv.org/abs/2602.08321)). MIT licensed.

Built by [`scripts/ingest_drsci.py`](../../scripts/ingest_drsci.py) from a pre-sampled 10K
handoff. The records carry no `difficulty` / `discrimination`: those are calibrated from real
judge responses, and until that fit exists the bank stays parameter-free rather than shipping
synthetic stand-ins that read like measurements.

**Current artifact: 10,003 scenarios · 98,611 criteria · 5-skill q-matrix · 7–19 criteria per
scenario (mean 9.86).**

> **Status: candidate benchmark — not confirmed for the bank.** Not wired into any default run.

## ⚠️ It ships its own rubrics — and that is the point

Unlike every other candidate, Dr. SCI **provides per-item criteria**, so this bank required no
hand-authoring (contrast [`data/Bridge`](../Bridge/README.md), where the whole 39-criterion set
had to be written by hand). The criteria here are **verbatim from the dataset**; the ingester
only adds the schema wrapper.

They are, however, **generated by OpenAI o3 and never human-verified**, because they were built
to be a reinforcement-learning *reward*, not a *score*. A reward tolerates noise that RL
averages away over millions of samples; an eval score does not. Treat individual criteria
accordingly.

## Scope: the open-ended half only

Dr. SCI has two structurally different halves:

| | open-ended (475,759) | verifiable (414,746) |
|---|---|---|
| rubrics | ~9.9 criteria per question | **none — `rubric` is `null`** (verified on 2,000 rows) |
| grading | LLM judge, per criterion | string/numeric match on one answer |
| outcomes per question | ~9.9 binary | **1** binary |
| has math? | **none** — authors deleted it as proof-heavy | ~45% of it |
| analogue in this repo | TutorBench | IFEval |

**This bank is the open-ended half.** The verifiable half cannot carry a criterion-level
q-matrix at all — it has no criteria — so its only options would be a single dimension or
subject-as-skill.

## The 5-skill q-matrix

Dr. SCI ships no skill labels, so the axis is ours. Worked examples and failure modes are in
[`SKILLS_AND_CRITERIA.md`](SKILLS_AND_CRITERIA.md).

| slug | % of items | % of positive weight | pure anchors | what it measures |
|---|---|---|---|---|
| `factual_recall` | 46.6% | 44.3% | 31,845 | the answer must CONTAIN a correct discrete claim |
| `mechanistic_reasoning` | 41.8% | 46.8% | 24,261 | the answer must SHOW WHY — chain, derivation, comparison |
| `quantitative` | 22.5% | 25.3% | 5,270 | formula, substitution, computation, units, precision |
| `presentation` | 18.1% | 15.7% | 3,686 | clear, ordered, appropriately concise |
| `restraint` | 6.8% | 3.8% | 1,440 | claims sized to evidence; hedging, scope, assumptions |

Multi-hot, so shares exceed 100%. Loadings per criterion: 1→66,502, 2→28,906, 3→3,145, 4→58.
No criterion is unmapped.

**On the two names.** `restraint` is deliberately *not* called "calibration": this repo
already uses that word for fitting the IRT model and for the pipeline `split` label, so a skill
by that name would be genuinely ambiguous. `presentation` is preferred over "communication"
because it says plainly that the criterion is about the *form* of the answer, not its content.

**Assignment is by pattern rules over criterion text. Aggregate shares are reliable; individual
row labels are not.** The recall/reasoning border is fuzzy for roughly a third of items, and
reasoning deliberately takes precedence there (explaining why subsumes stating what). A
hand-check of 16 random criteria found ~5 misassignments, mostly from words used in a different
sense ("presents", "defines", product numbers like `.357`).

### Why not the 8 subjects as skills

The obvious alternative, and it loses on four counts:

- **open-ended math is empty** — one of the eight skills would have zero items
- **physics is 63%** of the source pool and `science` is 1.2%; θ would be precise for one and
  noise for another
- **eight dimensions need 28 free latent correlations**, where this repo's own run already
  warned that *three* were not identifiable at n=82 (`staging/mirt_run1_console.txt`)
- **every criterion of a question would load on one skill**, so the ~9.9 criteria per question
  become replicate measures and the q-matrix carries no within-question information

`subject` is kept as a scenario field to stratify and slice on, which gives the same insight
without spending dimensions on it.

### Expect these dimensions to collapse — and let the calibration decide

On this repo's own 82-model TutorBench matrix (`staging/response_matrix.csv`, 485,615 real judge
verdicts), content-type dimensions do **not** separate: content↔quantitative r=0.943,
content↔presentation r=0.972, each↔total 0.97–0.99. It survives range restriction (r=0.919
among the top 10 models), `Qwen2.5-Math-7B` shows no advantage on quantitative criteria, and
`gpt2-large` tops that dimension — the signature of an artifact, not an ability.

Polarity is the one split that *did* separate there: negative-form criteria correlate only 0.40
with positive-form ones.

**That is TutorBench, not Dr. SCI** — a different benchmark, so treat it as a hypothesis rather
than a result. It costs nothing to test: `q_mapping` only affects how criteria are grouped when
fitting, not what gets judged, so the axis can be relabelled and refitted at zero API cost after
calibration. Ship the finer axis, then merge on evidence (`calibrate_mirt.py --collapse`).

## Fields the ingester adds

| field | from | note |
|---|---|---|
| `criticality` | Dr. SCI's own category tag | Essential→critical, Important→standard, Optional→optional, Pitfall→critical |
| `polarity` | category / negative weight | **16,732 items are `avoid`** — inverted (see below) |
| `source_weight` | Dr. SCI `weight` | −2…5, preserved with sign |
| `category` | description prefix | parses on 99.97%; 27 `Unlabelled` |
| `source_difficulty` | re-joined from the source parquet | recovered on **9,713/10,003** |
| `source_dataset` | re-joined | MegaScience 4,896 · natural_reasoning 3,570 · WebInstruct-Verified 1,104 |

The handoff had dropped `difficulty` and provenance; both were recovered by hashing question
text against the source parquet, reading only the `extra_info` column remotely (no 709 MB
download).

### Pitfall polarity

**17% of the bank is inverted.** A Pitfall criterion names something the response must NOT do,
and Dr. SCI gives it negative weight. This pipeline is binary pass/fail with no polarity
concept, so a Pitfall is scored **"did the response AVOID this mistake" — avoided = pass**. The
criterion text is left verbatim (the judge must read it as a thing to avoid) and the original
sign is kept in `source_weight`.

## ⚠️ `source_difficulty` is inverted

It is a **success rate** over 8 Qwen3-32B rollouts, so **higher means EASIER**. `1.0` is absent
because 8/8-solved questions were deleted as trivial. Sorting descending to get "hard" items
returns the easiest ones.

| value | scenarios | |
|---|---|---|
| **0.0** | **6,145 (63.3%)** | Qwen3-32B never solved these |
| 0.125 | 1,087 | |
| 0.25 | 672 | |
| 0.375 | 536 | |
| 0.5 | 453 | |
| 0.625 | 432 | |
| 0.75 | 388 | easiest retained |

**The 10K is subject-stratified but not difficulty-stratified** — 63.3% sits at the floor,
matching the pool's natural 63.1%. Combined with the authors having deleted the easy tail, the
bank is squeezed hard: weak models will fail nearly everything and yield little signal. Not
fatal, but plan for it, or re-pull stratified on both axes (the difficulty index is cached).

## Sampling

Subject-balanced at **exactly 1,429 per subject** across cs, medicine, biology, economics,
chemistry, physics, science. Referential integrity is exact: no duplicate ids, no orphan
rubrics, no missing or undeclared criterion ids.

The source was **cleaned before sampling** — see `clean_dr_sci_changelog.json`: 217,690 rubric
prefixes fixed, 17,701 equation fixes, 85 placeholder rows dropped from the open-ended half.

## Known limitations

- **Contamination is untested.** Dr. SCI is assembled from public corpora the models you would
  calibrate have plausibly trained on. The authors decontaminated against *their* benchmarks,
  not yours. Use `source_dataset` to reason about it.
- **Criteria are ~100% unique** — each was written for its own question, so no criterion is ever
  seen twice. Every item is a single-observation item: with ~90 models it gets ~90 observations
  and no pooling across questions is possible. **The skill labels are the only thing pooling
  information**, which makes the noisy assignment more consequential than it would be with a
  reusable bank.
- **Rubrics are o3-generated and unverified** (see above).
- **It is a training set, not a benchmark** — one `train` split, no held-out set, and the
  authors used it to train and then measured on GPQA / SuperGPQA / HLE / MMLU-Pro.
- `data/dr-sci/*.jsonl` is **gitignored** (line 92), so the bank is not committed; it is
  reproducible by re-running the ingester against the handoff.

## Rebuild

```
python scripts/ingest_drsci.py \
    --scenarios ~/Downloads/scenario_openended_10k.jsonl \
    --rubrics   ~/Downloads/rubrics_openended_10k.jsonl \
    --out-dir   data/dr-sci
```

`source_difficulty` requires `cache/drsci/difficulty_index.json`; without it that field is null
and everything else still builds.
