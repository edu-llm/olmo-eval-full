# IFEval

IFEval (Instruction-Following Eval, Zhou et al. 2023) reformatted into the Scenario +
Rubric schema. Source: https://huggingface.co/datasets/google/IFEval (one `train` split,
revision `966cd89545d6b6acfd7638bc708b98261ca58e84`).

Built by [`scripts/ingest_ifeval.py`](../../scripts/ingest_ifeval.py); the synthetic IRT
parameters are appended by [`scripts/assign_irt_params.py`](../../scripts/assign_irt_params.py).

> **Status: candidate benchmark — not confirmed for the bank.** IFEval is a *potential*
> option under evaluation, not a committed part of the calibration set. Whether it is used
> still needs further review. Its presence in `data/` does not mean it is wired into any
> run — the default bank in `config.yaml` remains TutorBench, and the integration below is
> only exercised when you explicitly flip to the IFEval axis. **Key review consideration:**
> IFEval measures *instruction-following only* (mechanical, verifiable constraints) — it has
> **no content-quality signal** (see "Skill axis" below). Keep it only if an
> instruction-following dimension is wanted in the bank; drop it if θ should reflect
> tutoring/content quality.

> **IFEval is graded by a deterministic code verifier, not the LLM judge.** Each criterion
> ships a machine-checkable constraint (e.g. "no commas", "≥300 words"). Grading is done by
> Google's `instruction_following_eval` checkers (vendored at
> [`tutor_cat/verifiers/ifeval/`](../../tutor_cat/verifiers/ifeval/)), reproduced at scoring
> time by [`IFEvalVerifier`](../../tutor_cat/ifeval_verifier.py). This is exact and needs no
> judge model — set `judge.backend: ifeval_verifier` for an IFEval run.

## What's in this folder

| File | Rows | What it is |
|------|------|------------|
| `scenarios.jsonl` / `.json` | 541 | one instruction-following prompt each (`.json` is a pretty-printed twin) |
| `rubrics.jsonl` / `.json`   | 834 | one binary criterion per instruction instance |
| `irt_logs/manifest.json`    | –    | synthetic-param run manifest (constants, seed, summary stats) |

- **541 scenarios, 834 criteria.** A prompt carries 1–3 instructions (305 have 1, 179 have
  2, 57 have 3); each instruction becomes one binary criterion.
- `.jsonl` is the canonical artifact; the `.json` twin holds identical records pretty-printed.

## How the source maps into the schema

| IFEval field | Schema field |
|--------------|--------------|
| `key` | `source_id` (join key back to HuggingFace) |
| `prompt` | `prompt` |
| `instruction_id_list[i]` | `verifier.instruction_id` + `q_mapping` category + `primary_skill` |
| `kwargs[i]` | `verifier.kwargs` (HuggingFace null-padding stripped) |
| `build_description(**kwargs)` | `criterion` (the checker's own constraint text) |

`verifier` is an **extra field** beyond the WildBench/InFoBench rubric schema:
`{"instruction_id": ..., "kwargs": {...}}`. It is the verifier's input, carried through
[`Rubric.from_json`](../../tutor_cat/schemas.py) (optional field, defaults to `None` for all
other benchmarks). `criterion` is generated by the checker's `build_description`, so it is
faithful, standalone text — e.g. `punctuation:no_comma` →
*"In your entire response, refrain from the use of any commas."*

## Skill axis (q-matrix)

The q-matrix is IFEval's own **9 instruction categories** (the `instruction_id` prefix),
single-hot — each instruction belongs to exactly one, like WildBench's one-skill mapping:

`keywords, detectable_format, length_constraints, change_case, startend, punctuation,
combination, detectable_content, language`

Criteria per category:

| category | criteria |
|----------|---------:|
| keywords | 163 |
| detectable_format | 157 |
| length_constraints | 143 |
| change_case | 89 |
| startend | 67 |
| punctuation | 66 |
| combination | 65 |
| detectable_content | 53 |
| language | 31 |

## Placeholders — what is real vs. synthetic

- **Real (from the dataset / verifier):** `prompt`, `criterion`, `verifier`, `q_mapping`,
  `primary_skill`. Grading itself (`y`) is **exact** — the deterministic verifier, not a judge.
- **Placeholder (uniform):** `criticality="critical"`, `explicitness="explicit"`, and
  `objectivity="objective"` (the last is genuinely true — the check is deterministic).
  These feed only the synthetic IRT heuristic; being uniform they add no per-item signal there.
- **Synthetic (`irt_params.source == "synthetic"`, `metadata_heuristic_v1`):** `difficulty`,
  `discrimination` — generated from the metadata above, **not** calibrated. Swappable later
  for calibrated values. Because grading is exact, a future real calibration over IFEval
  will be clean (no judge noise in `y`).

## Running IFEval (single-axis, one benchmark at a time)

The engine holds one skill axis at a time (`SKILLS` in
[`tutor_cat/__init__.py`](../../tutor_cat/__init__.py)), the same limitation WildBench (11
tags) and InFoBench (5 types) already carry. To run IFEval:

1. Set `SKILLS` in `tutor_cat/__init__.py` to the 9 IFEval categories (and adjust the
   `max_se` skill names in `config.yaml` / `run` accordingly).
2. Point `config.yaml` `data.scenarios`/`data.rubrics` at `data/IFEval/scenarios.jsonl` /
   `data/IFEval/rubrics.jsonl`.
3. Set `judge.backend: ifeval_verifier`.
4. `tutor-cat run` — `judge_results.jsonl` rows carry `judge_model="ifeval-verifier"`.

While `SKILLS` is set to the IFEval axis, TutorBench data is not loadable (its `q_mapping`
is keyed by `content/diagnosis/scaffolding`). Restore `SKILLS`/`config.yaml` afterwards.
This edit is per-run and **not committed** as a permanent change.

## Rebuilding

```bash
PYTHONPATH=. python scripts/ingest_ifeval.py
python scripts/assign_irt_params.py \
    --input data/IFEval/rubrics.jsonl \
    --skills keywords,detectable_format,length_constraints,change_case,startend,punctuation,combination,detectable_content,language \
    --log-dir data/IFEval/irt_logs --no-backup
```

Re-running the ingester strips the IRT params (it writes only the base schema fields), so
always re-run the assign step after a rebuild. The vendored verifier needs `langdetect`,
`immutabledict`, `absl-py`, and `nltk` with the `punkt` tokenizer data (see
[`tutor_cat/verifiers/ifeval/PROVENANCE.md`](../../tutor_cat/verifiers/ifeval/PROVENANCE.md)).
```bash
python scripts/smoke_ifeval_verifier.py   # sanity-check all 25 checkers
```
