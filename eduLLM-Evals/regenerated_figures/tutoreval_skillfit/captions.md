# TutorEval skill-fit figure set

Four figures assessing whether TutorEval's 2-skill axis
(`conceptual_understanding` vs `quantitative_procedural`) was a good fit.
All figures are regenerated by `scripts/plot_tutoreval_skillfit.py`, which reads
the source artifacts below **read-only** and invents no numbers.

| Figure | File | Data source |
| --- | --- | --- |
| 1 | `fig1_dimensionality.png` | `staging/tutoreval_calibration/calibration_mirt_manifest.json` |
| 2 | `fig2_skill_loading.png` | `staging/tutoreval_calibration/calibration_mirt.csv` + `data/TutorEval/rubrics_qmatrix_final.jsonl` (+ fitted-subset counts from the manifest) |
| 3 | `fig3_qmatrix_map.png` | `data/TutorEval/rubrics_qmatrix_final.jsonl` |
| 4 | `fig4_labeling_irr.png` | `qmatrix_verify_logs/full/manifest.json` |

## Fig 1 — Dimensionality panel (headline: TutorEval is effectively unidimensional)

Left: latent skill-correlation matrix, **ρ = 0.981** between
conceptual_understanding and quantitative_procedural (nearly collinear → one
effective axis). Right: AIC/BIC for the two fitted models — Unidimensional 2PL
(AIC 38966, BIC 60384) vs 2-skill M2PL (AIC 39137, BIC 61124); **ΔAIC = −171,
ΔBIC = −740** (uni − multi, both < 0 ⇒ both criteria favor the unidimensional
model). Caption notes **N = 52 models < 150** identifiability threshold, so the
multidimensional loadings are under-powered.

- Source fields: `latent_correlation[0][1]`, `comparison.uni.{aic,bic}`,
  `comparison.multi.{aic,bic}`, `comparison.delta_{aic,bic}_uni_minus_multi`,
  `n_persons_fit`, `identifiability.min_persons_identifiable`.

## Fig 2 — Skill-loading visual (the thin quantitative pool)

Left: per-skill discrimination distributions over the 1,186 fitted items —
conceptual **n = 1083, median a = 1.22** vs quantitative **n = 165,
median a = 1.61**. Right: q-pattern distribution for the full bank
(`10` conceptual-only = 1420, `01` quant-only = 161, `11` both = 107,
`00` unmapped = 98; total 1786) alongside the fitted subset
(`10` = 1021, `01` = 103, `11` = 62; total 1186). Callout: only
**165 / 1186 (≈ 14%)** fitted items load quantitative — the pool is thin.

- Discriminations computed from `a_conceptual_understanding` /
  `a_quantitative_procedural` (non-zero ⇒ loads that skill) in the item CSV.
- Full-bank q-patterns counted from `q_mapping` in the rubrics JSONL.
- Fitted-subset counts from `block.q_pattern_counts` in the manifest.

## Fig 3 — TutorEval Q-matrix map (aggregate analog of `data/IFEval/qmatrix_map.png`)

Left: a compact pattern×skill map (rows = the 4 q-patterns with counts, columns
= the 2 skills; a cell is shaded when that pattern loads that skill). Right:
criteria loading each skill over all **1786** criteria — conceptual
**1527 (85%)**, quantitative **268 (15%)**, overlap `11` = **107**, unmapped
`00` = **98**. An aggregate map is used instead of a 1786-row heatmap for
legibility. Conceptual dominates; quantitative is sparse; overlap is small.

- All counts derived from `q_mapping` in the rubrics JSONL
  (conceptual = `10` + `11` = 1420 + 107; quantitative = `01` + `11` = 161 + 107).

## Fig 4 — Labeling reliability (IRR)

Left: per-skill **Fleiss κ** (conceptual **0.686**, quantitative **0.722**) and
per-verifier **Cohen κ vs generator** (gpt-5.5: CU **0.669** / QP **0.807**;
gemini-3.1-pro: CU **0.676** / QP **0.673**) as grouped bars, with the
substantial-agreement band (κ ≥ 0.61) shaded. Right: the resolution breakdown
stacked bar — **unanimous 1477, majority 298, tie 10, generator_only 1**
(total 1786), with **review queue = 309 of 1786** annotated.

- Source fields: `stats.per_skill.<skill>.fleiss_kappa_all_raters`,
  `stats.per_skill.<skill>.cohen_kappa_vs_generator.<verifier>`,
  `resolution_counts`, `review_queue_size`, `input_records`.

## Notes / caveats

- Every annotated number traces to the cited source; none were invented. The
  full-bank q-pattern counts (1420/161/107/98) and per-skill discrimination
  medians (1.22 / 1.61) were recomputed directly from the raw files and match.
- `qmatrix_verify_logs/sample/manifest.json` was not needed; the full-mode
  manifest already carries every reliability and resolution number rendered.
- N = 52 persons < 150 means the multidimensional loadings and latent
  correlation in Fig 1 are statistically under-powered; the figure states this.
